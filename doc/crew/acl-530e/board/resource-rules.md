# 资源管控令（工头，09-29 14:15 起生效，优先于各礼包里的资源条款）

## 为什么
这台主机是共享的：4 核、15 GB 内存、**没有 swap**，根盘只剩约 1.7 GB。今天下午 15 分钟平均负载一度到 48，一部分来自我们班子几个席位同时跑 `-race` 和真容器测试。用户已经点名要求注意资源。

## 规则
1. **重负载命令一律通过闸门运行：**
   `CREW_SEAT=<你的席位> /tmp/crew/acl-530e/bin/heavy <命令…>`
   - 什么算重负载：任何 `go test`（包括按用例跑）、`go build ./...`、docker 真容器测试、`node scripts/test-*.mjs`、`npm test`、`npm ci`、`docker build`。
   - 闸门做四件事：
     - 全班同一时刻只放一个；
     - 以 `nice 15` 运行，设 `GOMAXPROCS=2`，go 的包并行度设为 2；
     - 1 分钟负载 ≥ 8、可用内存 < 3000 MB 或根盘剩余 < 1200 MB 时，持锁等待，每 30 s 复查一次；
     - 等待期间 stderr 会打印 `[heavy] hold …`，这是正常现象，不要绕过。
   - 排队和运行记录在 `/tmp/crew/acl-530e/heavy.log`。
2. **能按用例跑，就不要全量。** 每笔交付的全量 `-race` 只跑一次，就是报审前那一次。终审复用施工者的全量结果；终审自己只跑按用例的探针，再加一次全量。
3. **跑 `-race` 全量时，不要同时开真容器测试。** 两者分开跑，都要经过闸门。
4. **测试产生的 state 和临时目录跑完立即删除。** 真容器测试结束后，用 `docker ps -a --filter label=ai.easygo.workshop.owner=<你的 owner>` 确认没有残留。发现残留先报工头，不要自己去删别人的容器。
5. **不要新建 docker 镜像。** 现有夹具镜像够用。
6. 如果闸门等待超过 20 分钟，告诉工头，由工头判断，不要自己绕开。
