# Managed platform contract v1

Baseline 158b1b6. Three deployed core services remain: AI gateway, TS agent-loop (also authenticated Web), workshop (trusted Docker controller). Ephemeral task containers are not a fourth public service. Default dev tariff: 1000 total input+output tokens = 1 credit, represented as 1,000,000 integer microcredits per credit / 1000 microcredits per token. Cache counts are subsets of total input, never add them a second time. Registration enabled with zero balance; bootstrap admin and auditable idempotent grants, no payment processor.

## Browser/auth interface (web worker owns)

Export `createPlatform(config, callbacks)` from `src/platform/server.ts`. Config: `{listen,database,public_origin,secure_cookies,registration,bootstrap_admin?:{email,password_env}}`. Callback `{rpc(method,params):Promise<unknown>}` dispatches core agent/workshop/knowledge methods; params.namespace is always authenticated user's namespace injected by platform, never trusted from browser. Return `{server,address,wallet,close():Promise<void>}`. Node22 built-in SQLite; own platform DB; no new public deployment service.

Routes: POST /api/register {email,password}; POST /api/login {email,password}; POST /api/logout; GET /api/me; POST /api/rpc {method,params}; GET /api/wallet (balance/held/available and bounded ledger); GET /api/usage (bounded receipts); admin GET /api/admin/users, POST /api/admin/credits {user_id,amount_micros,reason,idempotency_key}, GET/PUT /api/admin/tariff. Optional admin explicit pending usage resolution must be audited. Auth uses scrypt salted passwords, opaque random session cookies (hash in DB), HttpOnly/SameSite, Origin check on state changes, rate limiting, strict object validation, no body/password logs. Public registration never grants admin/credits. Never infer identity from headers/body. Decimal UI, integer arithmetic/storage.

Public rpc allowlist: agent.session.create/list/history; agent.run.start/get/cancel/events; agent.workshop.catalog; workshop.submit/get/list/cancel/resume/result/events; agent.memory.list/upsert/delete/consolidate/import; agent.skills.list/get/upsert/delete/import. User can operate only own namespace. Foreman implements dispatch routing. Admin-only service config can be viewed without credentials; do not expose arbitrary RPC proxying or secret edits.

## Wallet mTLS interface (web worker implements pure wallet handlers; foreman mounts)

`wallet.reserve(p)` where p = `{namespace,request_id,fingerprint,model,reserve_input_tokens,reserve_output_tokens,source}`. Validate safe bounded integers. Atomically snapshot current tariff and reserve credits only if available balance suffices. Unique (namespace,request_id). Same fingerprint repeat returns same receipt with `duplicate:true`; new admission returns `duplicate:false`; changed fingerprint conflicts. Return `{reservation_id,tariff_version,reserved_micros,duplicate}`. Missing/disabled account fails. Insufficient balance is RpcError(-32002,'insufficient_credits'). Browser cannot call these methods.

`wallet.settle(p)` where p = `{namespace,request_id,usage:{known,input_tokens,output_tokens,cache_read_tokens?,cache_write_tokens?},outcome:'complete'|'rejected'|'uncertain',provider_status?,source}`. Known actual usage is durably retained and priced using the snapshotted tariff; raw token counts remain unchanged. Exactly-once debit and reservation release in one transaction. Duplicate identical settlement is no-op; conflicting replay rejected. Rejected/unbilled request releases hold; uncertain/missing usage remains pending, never silently free. Negative overage may be recorded explicitly rather than discard actual usage; prevent further admission. No automatic pending refund on timeout. Use integer microcredit math, safe overflow checks, cache subset validation. Append-only ledger/reconciliation audit; no balance overwrite from UI.

Internal RPC names `platform.wallet.reserve` and `platform.wallet.settle` with namespace validated by normal mTLS ACL. Only gateway identity receives them in managed deployment. Gateway reservation ID is original RPC request ID; fingerprint binds namespace/model/protocol/request hash. Gateway persists in-flight/outbox records before provider dispatch and settlement receipts before terminal success; crash/transport ambiguity stays pending for explicit reconciliation. Durable outbox retries idempotent settlements. Gateway is accounting authority for main loop, compaction/memory calls and CLI native requests; never bill CLI session-cumulative usage again. Direct unmanaged model routes are disabled in managed container mode.

## Knowledge interface (memory worker owns)

Export class `Knowledge` from `src/knowledge/index.ts`, config `{database,profile_limit?,consolidate_interval_ms?}`, dependency `{generate(namespace,messages):Promise<Response>}`. Methods: `prompt(namespace):Message[]`, `tools():Tool[]`, `execute(call,namespace,signal):Promise<unknown>`; `dispatch(method,params):unknown|Promise<unknown>` for RPC names above; `recordCompleted(namespace,run_id,messages):void` durable idempotent; `start():void`, `close():Promise<void>`. If exact integration type needs change, ask foreman first. Use independent SQLite knowledge DB. Foreman adds completed-turn outbox in agent Store.finish transaction, then drains into recordCompleted; no lost turns or failed-run memory.

Preserve eight old memory kinds, provenance, bounded profiles, explicit import/edit/delete and scheduled model consolidation checkpoints. Only own namespace material is recalled. Extraction results need source validation; model uses normal metered gateway. Skills catalog is lightweight; skill body fetched lazily via a bounded tool, names not paths. Explicit legacy export/import, no silent live DB mutation. Exported Go markdown profiles and skill folders may be imported through bounded trusted operator tool; do not claim migration of all old PostgreSQL/Eino sessions.

Remote TUI reuses existing Go Bubble Tea presentation via new network QueueManager adapter / cmd/easygo-remote; login to public platform API with password input, namespace bound by server. Supports session/history/task queue/cancel, reconnect/polling, runtime selection and memory/skill access where practical. No embedded Go agent execution in the remote path.

## Task containers (sandbox worker owns)

Workshop selects a mandatory Docker Runner when `sandbox.mode='docker'`; legacy host runner remains explicit opt-in for old tests/unmanaged usage, never fallback after Docker error. Each task invocation uses a distinct container, persistent task-only workspace/native HOME for resume, no host HOME, Docker socket, provider secret or service TLS private key inside it. Docker authority only in trusted workshop controller.

Network none for task containers; use one task-specific Unix socket mount for generation-only model relay. A small in-container shim exposes loopback HTTP to native CLI and forwards over the mounted UDS using temporary capability. Child cannot choose model/namespace/upstream or talk to host network. Only its workspace and per-run socket directory mounted. Rootfs read-only, non-root UID, capabilities dropped, no-new-privileges, bounded tmpfs/PIDs/CPU/memory, no privileged/host namespace devices. Container tool limits do not replace real isolation.

Docker controller must constrain image/paths/options to operator config, reject symlinks/out-of-root host mappings, kill/remove task container on cancel/timeout, reap orphan own labeled containers on restart without replay, never touch unrelated containers. CLI stdout still uses existing bounded native parser; artifacts checked from task workspace after completion. Managed compose exposes only Web; core RPC stays private mTLS. Worker supplies runtime image/controller image and isolated-runtime proof; foreman runs Docker/compose/load tests on dedicated daemon.

## Acceptance

Actual browser registration/login/admin credit grant -> balance -> user session/runtime choice -> metered main/CLI model call -> sandbox artifact -> debit/usage/history -> cancel/resume. Two-user isolation and insufficient-credit rejection before provider dispatch; concurrent reservations and duplicate receipts; durable gateway replay; malicious container filesystem/network/resource attempts denied; actual images built and started. Memory update/recall/consolidation and remote TUI hit TS chain. Long/complex project, concurrency and bounded soak fixtures with reproducible command, real duration/counts/latency/errors/recovery; no long-term stability claims beyond measured interval. Never expose credentials in evidence.
