## 故障注入（`scripts/test-platform-faults.mjs`）

真实进程 SIGKILL，本地夹具供应商：

| 场景 | 结果 |
|---|---|
| 钱包在 CLI 原生调用途中崩溃 | 网关 outbox 在恢复后结算，恰好一次 10,000 microcredits；loop 因 30 秒租约经 13 次重启尝试、25.3 秒后恢复 |
| loop 在流式调用途中崩溃 | 本次走「用量未知」分支：冻结、管理员按 20/5 token 结算、恰好一次；run 标为 interrupted，不重放 |
| 网关派发后崩溃 | 重启把在途记录转成 uncertain，冻结 4.598 积分，出现在待核对列表，管理员释放后余额不变；服务恢复可用 |
| 工坊在容器运行中崩溃 | 杀后留下 1 个孤儿容器，重启后回收为 0；任务 interrupted、只有 1 次执行 |
| 三服务正常重启 | 钱包、用量、历史完全一致 |
| 终局 | 9 次供应商请求 = 9 条钱包预留；余额 = 发放 − 185,000，冻结 0 |

独立审查曾证明早先版本的终局等式可被「后台记忆调用绕过计量」骗过；加入「供应商请求数 = 预留数」后，同一坏变体判红。

## 任务容器磁盘配额

16 MiB 配额、200 ms 轮询，真实容器：

| 用例 | 实测 |
|---|---|
| 单个大文件 | EFBIG，文件停在 16 MiB，任务失败、无产物 |
| 多个中等文件 | 超出 7.4 MiB 后被终止 |
| 大量小文件（上限 1000） | 在 1,184 个条目时被终止 |
| 轮询间隔 60 s、进程很快退出 | 退出后的终检仍拒绝（超出 8.4 MiB） |
| 两个 8 MiB 稀疏文件 | 只计实际占用 36 KiB，成功 |

超额任务 resume 被拒且不建容器，同时运行的正常任务不受影响。交叉审查发现 Resume 在全局锁内扫描，可让其他租户的操作等待约 565 ms；已修复，扫描期间跨租户取消实测 2.76 ms。

前两次尝试没有通过，也记录在此：第一次数据目录路径过长，模型转发 socket 超过 108 字节，任务在调用模型前就失败，没有花费（已加启动校验）；第二次输出上限设为 4096，每个写文件的响应都被截断，网关把截断的原生响应当作错误返回，两轮都在 25 秒内失败，用了 4 次调用。上限改为 32768 后通过，`configure-platform.mjs` 的默认值随之改为 32768。

这是一个项目、一个模型、一次成功样本，说明整条链路能支撑真实的多文件开发，不代表通过率。生成的项目与报告存于本机 `/home/ubuntu/reports/easygo-platform-20260928/live-project/codex-deepseek-flash-pass/`。

## 未完成与已知限制

- 真实模型只跑了 Codex + deepseek-flash 一个组合、一个样本；其余三个 CLI 和其他模型没有做复杂项目测试。
- 网关会把供应商返回的「截断」原生响应（`response.incomplete`）作为错误交给 CLI，而不是原样转发；输出上限设得够大时很少触发。
- 容量没有测过；单 IP 每分钟 300 次的限速本身就会限制单机压测。
- 用户在模型流式输出中途取消时，网关拿不到真实用量，积分会冻结到管理员处理。
- 没有 VM 隔离；磁盘配额是「软总量 + 硬单文件」；没有按用户的总磁盘预算，也不自动清理已结束任务的工作区。
- 交叉审查正在复现一个低概率竞态：任务退出与取消同时发生时，超额工作区的任务可能以 cancelled 结束并登记产物。数据已经在盘上，resume 仍会被拒，因此不会造成额外写入。结论出来后更新本节。
- 测试用 Docker daemon 未证明核心容器能出网，不能直接当生产模板。
