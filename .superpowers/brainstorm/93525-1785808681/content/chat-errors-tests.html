错误边界与测试护栏

保持现有 HTTP/SSE 错误语义，同时让各层可以独立测试和诊断。

错误如何跨越边界
MySQL Adapter

将 GORM 的未找到、重复键、数据库故障映射为项目级错误；回滚事务。

↓
Chat Application

处理 DuplicateRequest、Conflict、NotFound 与运行终态，不识别 GORM 错误。

↓
Controller

继续使用现有 errorcode、HTTP 状态码和 SSE error/run 事件。

客户端断开或请求取消后，Finalize 使用独立 10 秒 Context，避免 active_run_id 残留。
逐层结构化日志
Repository
记录数据库操作、实体 ID、错误。
Use Case
记录业务动作、user/session/run/request ID、错误。
Controller
记录接口投影失败和安全请求标识。
每一层在返回错误前记录一次；使用 zap 类型字段。绝不记录 Prompt、聊天内容、API Key、Token 或凭证密文。
