聊天运行：数据流与事务边界

目标：事务短小、业务原子性不变、网络与 Eino 执行永不占用数据库事务。

阶段 1 · Prepare
事务外：快速准备
  1. 校验 input / request_id
  2. 幂等快速查询
  3. 校验会话与模型
  4. 解析 ModelSpec
  5. 构建 AgentRunner
→
单个 MySQL 事务
  1. 锁定 Session
  2. 二次校验模型、Active Run 与幂等键
  3. 创建 AgentRun 并占用 Session
  4. 一次分配用户消息序号并写入
  5. 读取最近历史快照

TransactionManager 传入事务作用域 Repository，不暴露 *gorm.DB。

→
PreparedRun
  • Run / Session 快照
  • 项目级 AgentRunner 接口
  • 已组装的历史消息
  • 开始时间
阶段 2 · Execute（无数据库事务）
发送 running
→
带 Deadline 执行 Runner
事件映射为现有 SSE
→
判定终态
成功 / 失败 / 取消

客户端断开、运行超时、Eino 错误只影响终态判定；执行期间不持有数据库连接或行锁。

阶段 3 · Finalize
事务外：整理输出
  • 转换所有输出消息
  • 计算 token 与 latency
  • 截断错误文本
→
独立 10 秒 MySQL 事务
  1. 一次批量预留 N 个消息序号
  2. 内存循环填充序号（循环内无 SQL）
  3. 批量写入 assistant 消息
  4. 更新 Run 终态与 Session 统计
  5. 释放 active_run_id
→
尽力发送终态 SSE 持久化优先；发送失败不回滚数据库
关键规则：业务层决定事务内的步骤；MySQL 适配器只实现这些步骤。任何 SQL 都不会出现在循环中。
