## 现场 / 锚点
依据是 `board/review-w2-aa41e65.md` 的两条 P3。

1. **只读挂载靠子串匹配。**
   - `containerOptions`（`docker.go`，生成 `type=bind,src=…,dst=/workspace,bind-propagation=rprivate`）生成工作区挂载串以后，有两处去找 `,dst=/workspace,` 子串，找到了才在末尾追加 `,readonly`：
     - `checkContainerOptions`（`acceptance_docker.go`）；
     - `taskContainerOptions` 的 read-only 策略分支（`docker.go`，W-4 以前就有）。
   - 挂载串里字段的顺序一变，就会**悄悄**丢掉 `readonly`。终审把 `dst` 挪到最后一个字段，测试 `TestAcceptanceContainerOptions` 才判红；它锁的是整段字面量，并没有断言"工作区一定只读"。
   - 这是安全边界：检查容器和 read-only 工作流都依赖工作区只读。
2. **重启时留下旧的 false_green。**
   - `finish`（`service.go:737-739`）在任务仍是 Running 或 Cancelling、终态却是 Interrupted 时，把 `acceptance.state` 改写成 `interrupted`，但不重算 `false_green`。
   - 于是可能出现 `interrupted` + `false_green=true`，违反真值表：false_green 只可能在 submitted、`tests=pass`、`failed` 三者同时成立时为真。
   - 复现：终审的探针 `TestReview2InterruptedFinishKeepsFalseGreen`，在 `/tmp/crew/acl-530e/review2/aa41e65/`。
   - 所有 `finish` 调用之后都紧跟着 `finishCrewOutcome(tx, task)`（`crew.go:305`），见 `service.go:230/475/705/804`。

## 修法
1. **在构造时就决定工作区挂载是否只读，不再事后改字符串。**
   - 给 `containerOptions` 加一个 `workspaceReadOnly bool` 参数（或者等价的显式写法），在生成挂载串时直接带上 `readonly`。
   - 删掉 `checkContainerOptions` 和 `taskContainerOptions` 里两处子串匹配。
   - 检查容器总是只读；task 容器只在 `policy == "read-only"` 时只读，`.workshop-home` 子挂载照旧可写。
   - `Initialize` 的探针容器挂载保持现状：不加 `readonly`，行为不变。
2. **`finishCrewOutcome` 在重算 outcome 之后，按同一张真值表重算 `run.Acceptance.FalseGreen`**：用 `falseGreen(outcome, tests, state)`，tests 取本 run 最后一条 from_worker submit 的 `claims.tests`，和 `acceptanceFalseGreen` 的口径一致，最好直接复用它。
   - 如果 finish 路径上会为状态变化发 acceptance 事件，事件里的 false_green 也必须是重算后的值；不发事件的，不要新增事件。
   - 不改 `finish` 把已完成的验收改写成 `interrupted` 的既有选择。那是 W-2 的设计，这一单只修一致性。

## 明令不做
- 不改挂载的其它字段和顺序，也不改 `.workshop-home` 子挂载。
- 不改 W-5 的回收逻辑，不改 outcome 的判定规则。
- 不新增 acceptance 状态。
